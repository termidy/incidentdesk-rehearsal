## Goal
Expose a stable mobile endpoint that returns an incident with its timeline oldest first and the specified not-found response.

## Steps
1. Add `GET /mobile/v1/incidents/{key}` and its response schemas in the issue-owned router module `incidentdesk/api/mobile_incident_detail.py`.
2. Register that router in `incidentdesk/app.py`, using an issue-specific import and one `include_router` line.
3. Add `tests/api/test_mobile_incident_detail.py` for the response example, chronological timeline ordering, and the unknown-key status and body.
4. Add one plain-language line under `## Unreleased` in `CHANGELOG.md`.

## Tests
- `tests/api/test_mobile_incident_detail.py` verifies the incident fields, timeline event shape and order, and that an unknown key returns 404 with `{"error":"not_found"}`.
- Run `pytest tests/api/test_mobile_incident_detail.py`.

## Risks
- **Files owned by #42:** `incidentdesk/api/mobile_incident_detail.py` and `tests/api/test_mobile_incident_detail.py`.
- **Shared files touched:** `incidentdesk/app.py` (this issue's distinct router import and one registration line) and `CHANGELOG.md` (one distinct entry). Keep these additions separate from #41 and #43 so the branches can merge without overwriting each other's lines.
- Assert the exact mobile-specific error body rather than relying on FastAPI's default 404 response.
- #42 does not depend on #41 or #43.

## Out of scope
- Incident listing and pagination from #41.
- Alert subscriptions from #43.
- Mobile API documentation requested separately in #44 and changes to internal incident endpoints.
