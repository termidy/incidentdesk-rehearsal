## Goal

Require incident titles submitted to `POST /incidents` to contain 1–200 characters after surrounding whitespace is removed.

## Steps

1. Update `incidentdesk/schemas.py` so `IncidentIn` strips surrounding whitespace before enforcing a 1–200 character limit.
2. Keep `incidentdesk/incidents.py` title normalization in place so accepted titles are saved without surrounding whitespace.
3. Add API tests in `tests/api/test_incidents.py` for whitespace-only rejection without creating an incident, rejection at 201 characters, acceptance at 200 characters, and saving `"  Login fails  "` as `"Login fails"`.
4. Add a plain-language entry under Unreleased in `CHANGELOG.md`.

## Tests

- Whitespace-only title returns 422 and creates no incident: add an API test that checks the response and empty incident list.
- 201-character title returns 422: add an API test.
- 200-character title is accepted: add an API test that checks the saved title.
- `"  Login fails  "` is saved as `"Login fails"`: retain the existing API assertion and add explicit whitespace coverage if needed.
- Run `pytest -q tests/api/test_incidents.py` with `DATABASE_URL` set, then run `pytest -q` for the whole suite.

## Risks

- Applying the length limit before stripping would reject valid boundary inputs or accept whitespace-only values; API boundary tests will catch this.
- Changing normalization behavior in the lifecycle could affect non-API incident creation; retain its existing stripping behavior.

## Out of scope

Existing incidents, `/mobile/v1`, alert intake, and title validation on any other input path.
