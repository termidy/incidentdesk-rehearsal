## Goal
Let an engineer create and list persisted alert subscriptions through the mobile API, rejecting subscriptions that name unknown services.

## Steps
1. Add the subscription model to `incidentdesk/models.py`, with an identifier and fields for engineer, services, and minimum priority.
2. Add `POST /mobile/v1/subscriptions`, `GET /mobile/v1/subscriptions`, and their request/response schemas in the issue-owned router module `incidentdesk/api/mobile_subscriptions.py`. Validate requested service slugs against existing services before saving.
3. Register that router in `incidentdesk/app.py`, using an issue-specific import and one `include_router` line.
4. Add `tests/api/test_mobile_subscriptions.py` for creation, engineer-scoped listing, returned IDs, and unknown-service rejection.
5. Add one plain-language line under `## Unreleased` in `CHANGELOG.md`.

## Tests
- `tests/api/test_mobile_subscriptions.py` verifies a valid POST returns 201 and the stored fields with an ID, GET lists only the requested engineer's subscriptions, and an unknown service returns 422 without creating a subscription.
- Run `pytest tests/api/test_mobile_subscriptions.py`.

## Risks
- **Files owned by #43:** `incidentdesk/api/mobile_subscriptions.py`, `tests/api/test_mobile_subscriptions.py`, and `incidentdesk/models.py` (only #43 adds the subscription model).
- **Shared files touched:** `incidentdesk/app.py` (this issue's distinct router import and one registration line) and `CHANGELOG.md` (one distinct entry). Keep these additions separate from #41 and #42 so the branches can merge without overwriting each other's lines.
- Validate all service slugs before saving so an invalid subscription cannot be persisted.
- #43 does not depend on #41 or #42.
