## Goal
Provide a Markdown export for complete postmortems while withholding drafts without a root cause.

## Steps
1. Add `GET /postmortems/{key}/export.md` to `incidentdesk/api/postmortems.py`, returning a Markdown document with the title, incident key, Summary, Impact, Root cause, and Actions as checklist items; use published PM-101 and PM-102 as references, and do not export a postmortem with no root cause.
2. Extend `tests/api/test_postmortems.py` to verify the response content type and document structure, checklist formatting, missing-key behavior, and refusal to export a draft without a root cause.
3. Add a plain-language entry under `## Unreleased` in `CHANGELOG.md`.

## Tests
- Verify an exported published postmortem includes its title and incident key, all required sections in order, and actions formatted as Markdown checklist items in `tests/api/test_postmortems.py`.
- Verify a draft without a root cause is not exported in `tests/api/test_postmortems.py`.
- Run `tests/api/test_postmortems.py` to confirm the new route and existing postmortem API behavior.

## Risks
Incorrect Markdown escaping or section ordering could make the wiki document hard to read; response-content assertions will catch formatting regressions. Accidentally exporting an incomplete draft could share unfinished incident analysis; a draft-specific test will verify it is refused.

## Out of scope
Changing postmortem storage, publication requirements, or other postmortem endpoints.
