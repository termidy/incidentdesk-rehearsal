## Goal
Allow teams to download a completed postmortem as a Markdown document through the API.

## Steps
1. Add `GET /postmortems/{key}/export.md` in `incidentdesk/api/postmortems.py`, returning the title, incident key, Summary, Impact, Root cause, and Actions as a Markdown checklist; reject postmortems without a root cause.
2. Add focused endpoint tests in `tests/api/test_postmortems.py` for document content, Markdown response type, missing postmortems, and drafts without a root cause.
3. Add a plain-language entry under Unreleased in `CHANGELOG.md`.

## Tests
- A finished postmortem exports all required information and each action as a checklist item: assertions in `tests/api/test_postmortems.py`, modeled on published demo postmortem PM-101.
- A postmortem without a root cause is not exported: assertion in `tests/api/test_postmortems.py` using draft PM-117.
- An unknown key returns not found: assertion in `tests/api/test_postmortems.py`.
- Existing postmortem API behavior remains intact: run `pytest tests/api/test_postmortems.py`.

## Risks
Markdown formatting can obscure or omit content, especially action items; verify the generated text and content type through the API test. The export must not expose incomplete drafts.

## Out of scope
Do not add Markdown editing or import support, change postmortem publication rules, or alter the existing JSON endpoints.
