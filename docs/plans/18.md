## Goal
Add `GET /postmortems/{key}/export.md` to return a published postmortem as Markdown and refuse to export drafts without a root cause.

## Steps
1. Update `incidentdesk/api/postmortems.py` to add the export route, returning a Markdown response with the postmortem title, incident key, Summary, Impact, Root cause, and Actions rendered as a checklist; reject drafts without a root cause.
2. Update `tests/api/test_postmortems.py` to cover the exported content, section ordering, checklist formatting, and draft rejection.
3. Update `CHANGELOG.md` under `## Unreleased` to mention Markdown postmortem export.

## Tests
- A request for a published postmortem returns Markdown containing its title, incident key, all required sections, and actions as checklist items: `pytest tests/api/test_postmortems.py` (requires `DATABASE_URL`).
- A draft with no root cause is not exported: `pytest tests/api/test_postmortems.py` (requires `DATABASE_URL`).

## Risks
- The route could accidentally expose incomplete draft content; test that a draft without a root cause receives a non-success response.
- Markdown labels or checklist formatting could diverge from the expected wiki document; assert the response media type, section order, and action item format.

## Out of scope
- Changing postmortem creation, editing, or publication rules.
- Adding exports in formats other than Markdown.

Published postmortem PM-101 was used as the finished-postmortem reference.
