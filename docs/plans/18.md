## Goal
Allow teams to download a completed postmortem as Markdown through `GET /postmortems/{key}/export.md`.

## Steps
1. Add the Markdown export route to `incidentdesk/api/postmortems.py`, returning the title, incident key, Summary, Impact, Root cause, and Actions as a checklist; reject export when the root cause is missing and return 404 for an unknown key.
2. Add focused endpoint tests in `tests/api/test_postmortems.py` for the Markdown content, checklist formatting, missing-root-cause draft, and unknown key.
3. Add a plain-language entry under Unreleased in `CHANGELOG.md`.

## Tests
- A finished postmortem export returns Markdown with its title, incident key, all required sections, and actions rendered as checklist items: assertions in `tests/api/test_postmortems.py`.
- A postmortem without a root cause is not exported: assert the draft export returns the chosen client error in `tests/api/test_postmortems.py`.
- An unknown postmortem key returns 404: assert in `tests/api/test_postmortems.py`.
- Existing postmortem API behavior remains intact: run `pytest tests/api/test_postmortems.py`.

## Risks
The export must distinguish drafts without a root cause from missing postmortems, and its response must advertise a Markdown media type; the endpoint tests should verify both.

## Out of scope
Do not add postmortem editing or publication workflows, change the existing JSON endpoints, or alter the postmortem data model.
