## Goal
Replace every use of pytz with the standard-library `zoneinfo`, remove the pytz dependency, and preserve existing timezone behavior, including daylight-saving transitions.

## Steps
1. **Core and reporting time handling (12 Python files):** Migrate `incidentdesk/timeutil.py`, `incidentdesk/models.py`, `incidentdesk/config.py`, `incidentdesk/seed.py`, `incidentdesk/sla.py`, `incidentdesk/cli.py`, `incidentdesk/reports/daily.py`, `incidentdesk/reports/weekly.py`, and `incidentdesk/reports/mttr.py`; update `tests/conftest.py`, `tests/unit/test_timeutil.py`, and `tests/unit/test_reports.py` in the same step. Preserve UTC handling and report timezone validation/formatting, and add or adjust focused tests for DST boundaries and ambiguous local times.
2. **Ingest, maintenance, API, and on-call (13 Python files):** Migrate `incidentdesk/ingest/webhook.py`, `incidentdesk/ingest/email_parser.py`, `incidentdesk/ingest/dedupe.py`, `incidentdesk/maintenance/windows.py`, `incidentdesk/api/timeline.py`, `incidentdesk/api/incidents.py`, `incidentdesk/oncall/schedule.py`, `incidentdesk/oncall/handoff.py`, and `incidentdesk/oncall/rotation.py`; update `tests/unit/test_ingest.py`, `tests/unit/test_maintenance.py`, `tests/unit/test_oncall.py`, and `tests/unit/test_routing.py` alongside their affected behavior. Verify localized schedule and maintenance times around daylight-saving transitions.
3. **Remaining modules and dependency removal (16 Python files, plus project metadata):** Migrate `incidentdesk/retention/cleanup.py`, `incidentdesk/exporters/csv_export.py`, `incidentdesk/escalation/timers.py`, `incidentdesk/notify/digest.py`, `incidentdesk/notify/email.py`, `incidentdesk/notify/chat.py`, `incidentdesk/statuspage/history.py`, `incidentdesk/statuspage/publisher.py`, and `incidentdesk/audit/trail.py`; update `tests/unit/test_escalation.py`, `tests/unit/test_notify.py`, `tests/unit/test_audit.py`, `tests/unit/test_retention.py`, `tests/unit/test_statuspage.py`, and `tests/unit/test_priority.py`. Remove pytz from `pyproject.toml` only after no imports remain, and update `doctor.py` so its dependency check no longer requires pytz. Run the full suite and search the repository for remaining pytz usage.

Across all steps, follow `.github/instructions/migration.instructions.md`; pay particular attention to the differences between pytz `localize()`/`normalize()` and `ZoneInfo` attachment and arithmetic. Use `docs/progress/24.md` as the shared one-line-per-file checklist, ticking each file only when it is done, and `docs/decisions.md` as the shared decision log, recording each decision with its reason. Keep each step green before beginning the next.

## Tests
- Each step's affected unit tests prove its migrated code and fixtures still work; run those focused tests before completing that step.
- DST and ambiguous-time regression cases in the relevant timezone/report, maintenance, and schedule tests prove the replacement preserves the established transition behavior.
- `pytest -m 'not db'` after each step verifies the non-database suite remains green.
- After step 3, run the full configured test suite (`pytest`) and confirm no pytz imports or dependency references remain.

## Risks
- `ZoneInfo` attaches directly to datetimes and does not provide pytz's `localize()` or `normalize()` semantics; ambiguous and nonexistent wall times and arithmetic across DST changes could shift behavior. Focused transition tests and stepwise test runs make regressions visible.
- Removing pytz before all production, test, and tooling references are migrated could break imports or dependency checks. Defer dependency removal to the final step and search all repository files before completing it.

## Out of scope
- Changing timezone defaults, user-visible time formats, scheduling rules, or the supported Python version.
- Unrelated dependency updates or broad datetime refactoring.
